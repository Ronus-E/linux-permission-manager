------------------------------------------------------------
23. Calcul des permissions
------------------------------------------------------------

Les valeurs sont :

r = 4
w = 2
x = 1

Donc :

r-- = 4

-w- = 2

--x = 1

rw- = 4 + 2 = 6

r-x = 4 + 1 = 5

rwx = 4 + 2 + 1 = 7


------------------------------------------------------------
24. Permission 600
------------------------------------------------------------

600 signifie :

6 pour le propriétaire
0 pour le groupe
0 pour les autres

Donc :

600

correspond à :

rw-------

Le propriétaire possède :

r + w

Le groupe ne possède aucun droit.

Les autres ne possèdent aucun droit.


------------------------------------------------------------
25. Permission 640
------------------------------------------------------------

640 signifie :

6 pour le propriétaire
4 pour le groupe
0 pour les autres

Correspondance :

rw-r-----

Propriétaire :

rw- = 6

Groupe :

r-- = 4

Autres :

--- = 0


------------------------------------------------------------
26. Permission 644
------------------------------------------------------------

644 signifie :

6 pour le propriétaire
4 pour le groupe
4 pour les autres

Correspondance :

rw-r--r--

Propriétaire :

rw- = 6

Groupe :

r-- = 4

Autres :

r-- = 4


------------------------------------------------------------
27. Permission 700
------------------------------------------------------------

700 signifie :

7 pour le propriétaire
0 pour le groupe
0 pour les autres

Correspondance :

rwx------

Propriétaire :

rwx = 7

Groupe :

--- = 0

Autres :

--- = 0


------------------------------------------------------------
28. Permission 755
------------------------------------------------------------

755 signifie :

7 pour le propriétaire
5 pour le groupe
5 pour les autres

Correspondance :

rwxr-xr-x

Propriétaire :

rwx = 7

Groupe :

r-x = 5

Autres :

r-x = 5

PARTIE 18 — PIPE
============================================================


------------------------------------------------------------
78. |
------------------------------------------------------------

Le symbole `|` peut avoir plusieurs significations selon
le contexte.

Dans un pipeline :

commande1 | commande2

la sortie de `commande1` est envoyée vers `commande2`.

Exemple utilisé :

sed -n '75,90p' perm-manager.sh | cat -n

Fonctionnement :

sed
 |
cat


`sed` produit du texte.

Le pipe transmet ce texte.

`cat -n` reçoit le texte et ajoute les numéros de lignes.


IMPORTANT :

Le `|` d'un pipeline n'a pas le même rôle que le `|` dans
un `case`.

Dans :

600|640|644

`|` signifie :

OU.

Dans :

sed ... | cat

`|` signifie :

envoyer la sortie vers la commande suivante.

84. Fonction is_valid_permission
------------------------------------------------------------

Code :

is_valid_permission() {
    local permission="$1"

    case "$permission" in
        600|640|644|700|755)
            return 0
            ;;
        *)
            return 1
            ;;
    esac
}

Cette fonction vérifie si la permission est autorisée.

Permissions autorisées :

600
640
644
700
755


------------------------------------------------------------
85. Fonction check_file
------------------------------------------------------------

Code :

check_file() {
    local file="$1"

    if [ -f "$file" ]; then
        return 0
    elif [ -d "$file" ]; then
        echo "Error: Path is a directory."
        return 1
    else
        echo "Error: File does not exist."
        return 1
    fi
}

Cette fonction vérifie si le chemin correspond à un fichier.

Si c'est un fichier :

return 0

Si c'est un dossier :

echo "Error: Path is a directory."

return 1

Si le chemin n'existe pas :

echo "Error: File does not exist."

return 1


------------------------------------------------------------
86. Fonction apply_permission
------------------------------------------------------------

Code :

apply_permission() {
    local permission="$1"
    local file="$2"

    if chmod "$permission" "$file"; then
        echo "Permission $permission applied successfully."
        return 0
    else
        echo "Error: Failed to change permissions."
        return 1
    fi
}

La fonction reçoit :

$1 = permission

$2 = fichier


Exemple :

apply_permission "644" "notes.txt"

Elle exécute :

chmod "644" "notes.txt"

PARTIE 25 — ORDRE COMPLET DU SCRIPT

100. Ordre d'exécution
------------------------------------------------------------

Le programme suit cette logique :

1. Bash lit le shebang.
